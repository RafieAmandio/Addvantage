- [2026-04-18 tick 125] **Convention** — Postgres `INSERT ... ON CONFLICT (col) WHERE <predicate>` requires an exact predicate match against a partial unique index. When broadening a partial unique index (e.g. from `kind='news'` to `kind in ('news','tweet')`), you must `drop index` + `create unique index ... where <new predicate>` **and** update every `ON CONFLICT ... WHERE` caller in the same migration; otherwise the statement errors with "no unique or exclusion constraint matching the ON CONFLICT specification". _packages/db/migrations/0015_trump_source_and_tweet_kind.sql_

- [2026-04-18 tick 127] **Gotcha** — the ForexFactory weekly RSS (`nfs.faireconomy.media/ff_calendar_thisweek.xml`) publishes `<date>MM-DD-YYYY</date>` + `<time>H:MMam/pm</time>` (or literal "All Day" / "Tentative") in US Eastern, never UTC and without an explicit offset. Parsing by string-concatenation into `YYYY-MM-DDTHH:MM:00-04:00` (fixed EDT) yields ≤1h drift across the DST boundaries but is good enough for day-scope macro events; don't be fooled into treating the values as UTC. Also: under tsconfig `noUncheckedIndexedAccess`, regex capture groups are `string | undefined` even inside the `if (match)` branch — assert with `!` on each group (or destructure with defaults) to keep `parseInt`/`.toLowerCase()` type-safe. _apps/worker/src/adapters/forexfactory.ts_
- [2026-04-18 tick D4] **Gotcha** — `<input type="datetime-local">` submits `YYYY-MM-DDTHH:MM` (no seconds, no timezone offset), which does NOT satisfy zod's `z.string().datetime()` (requires ISO 8601 with `Z` or offset). In a React server-action form, drive the visible input with component state and mirror the serialised value into a sibling `<input type="hidden" name="occurredAt" value={new Date(localDt).toISOString()} />` — the hidden field is what the FormData carries. Don't try to transform in the server action: the FormData entry is already truncated. _apps/web/features/timeline/components/AddPinButton.tsx_
